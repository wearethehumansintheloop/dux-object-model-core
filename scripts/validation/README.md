# DUX Object Model Validation (Generation-First)

This directory contains the **Generation-First HITL validation pipeline** for DUX Object Model Core.

## 🎯 Generation-First Principle

**All validation artifacts are GENERATED from canonical markdown, never manually maintained.**

- ✅ **Validation scripts** → Generated by Stage 4
- ✅ **JSON schemas** → Generated from docling markdown  
- ✅ **BDD tests** → Generated by Stage 5
- ✅ **Frame-aware prompts** → Generated by Stage 6

## 📁 Directory Structure

### `hitl_pipeline/` - Active Generation-First Pipeline
- **`hitl_orchestrator.py`** - Complete 6-stage validation workflow
- **`stage1_structure_validation.py`** - Markdown template validation
- **`stage2_consistency_validation.py`** - Content consistency checks
- **`stage3a_problem_docling_md.py`** - Docling markdown generation (canonical format)
- **`stage3b_*_schema_validation.py`** - Schema compliance validation
- **`stage4_object_validation.py`** - **GENERATES validation scripts**
- **`stage5_bdd_generator.py`** - **GENERATES BDD test artifacts**
- **`stage6_prompt_generator.py`** - **GENERATES Frame-aware prompts**

### `archive_obsolete_validation_scripts/` - Historical Artifacts
- All manually-maintained validation scripts (`.OBSOLETE`)
- Broken docling implementations (`.BROKEN`) 
- Incomplete pipeline attempts (`.INCOMPLETE`)
- Old configuration files (`config.py.OBSOLETE`)

### `utilities/` - Helper Functions
- **`duplicate_handler.py`** - HITL queue duplicate management

## 🚀 Usage

### Primary Entry Point
```bash
# Run complete Generation-First validation pipeline
python hitl_pipeline/hitl_orchestrator.py
```

### Individual Stages (for debugging)
```bash
# Generate validation script from canonical markdown
python hitl_pipeline/stage4_object_validation.py <docling_markdown_path>

# Generate BDD tests from canonical markdown  
python hitl_pipeline/stage5_bdd_generator.py <docling_markdown_path>

# Generate Frame-aware prompts from canonical markdown
python hitl_pipeline/stage6_prompt_generator.py <docling_markdown_path>
```

## 🔄 Integration with Frame-Aware System

Generated artifacts feed the Frame-aware extraction system:
- **Validation scripts** → Ensure object quality
- **BDD tests** → Prevent regression
- **Frame-aware prompts** → Power contextual agent generation

## ⚠️ Important Notes

- **NEVER manually edit** validation scripts, schemas, or prompts
- **If something is wrong** → Fix the canonical markdown source and regenerate
- **Generation-First** → All artifacts must be reproducible from canonical sources

## 📊 Pipeline Flow

```
Canonical Markdown → Docling → Generated Artifacts
     ↓                ↓            ↓
   Stage 1-3      Stage 4-6    Frame-Aware
  Validation     Generation     Agents
```
